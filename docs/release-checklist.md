# 发布检查清单

本清单用于有限范围的测试 APK 交付，不代表应用已具备正式公开发布条件。请勿据此推送、提交应用商店或公开发布。

## 公开分发前的作者决策

- [ ] **选择并配置长期 Android 正式签名身份。** 当前 `release` 构建仍使用开发/debug 密钥，不适合公开分发或持续更新。作者须先决定签名密钥的安全保管、备份与签名流程。不要将密钥、密码或本地签名配置提交到仓库，也不要替作者生成密钥或决定保管方式。首次分发后若更换签名身份，Android 不会接受为原位更新；用户可能需要卸载并丢失本地数据。**正式签名尚未由作者配置前，不得公开分发。**
- [ ] 决定公开分发渠道和版本策略。每次公开更新的 Android `versionCode` 必须严格递增；`versionName` 用作用户可见版本号；更新必须沿用同一签名身份。版本变更由发布负责人决定。
- [ ] 仅当作者也决定公开应用源代码时，才由作者选择仓库源码许可。仅分发 APK 时，此项不是 APK 发布前提；发布工具不得推断或代选源码许可。

## 向测试者交付 APK 前

- [ ] 确认交付的是统一 Release APK，并核对其签名身份；不要把 Debug、Profile 或按 ABI 拆分的 APK 当作标准交付包。
- [ ] 确认设置中的“隐私说明”显示 [`PRIVACY.md`](../PRIVACY.md) 链接的对应语言版本，并依据实际清单、存储及导入／导出行为核对其内容。
- [ ] 确认实际 APK 包含 `assets/fonts/` 下六份完整 SIL OFL 文本，且应用内开源许可页可阅读全部文本。分发内置及下载字体时均须按许可要求保留版权声明和许可文本。
- [ ] 核对 Flutter 与其他第三方依赖的许可，以及实际要交付的 APK；不要把本地诊断文件、构建中间产物误当成发布文件。
- [ ] 正式签名配置完成后，由发布负责人在目标设备上验证最终 APK 的安装、启动、同签名更新，以及系统备份／恢复流程。当前本地验证不替代这些场景的实机检查。
- [ ] 向测试者说明数据丢失与备份风险，并仅在作者已建立支持渠道时提供反馈方式；不要编造联系邮箱或网址。

## 有限范围测试与数据风险说明

请测试者使用专用测试设备和可丢弃数据，尝试普通笔记创建／编辑、换卷与历史浏览、通知权限和提醒设置，以及手动备份导出／导入。通知实际送达情况受目标设备及 Android 厂商省电策略影响；建议在目标系统上验证。这些只是有限范围测试建议，不代表覆盖所有设备或场景。

笔记文件以明文保存在应用私有存储中。清单未关闭 Android 系统备份；系统可能依设备、帐号及平台策略备份或迁移笔记与提醒文件。用户选择的导出位置可能由第三方或云端文件提供方处理。卸载或清除应用数据会删除应用私有数据；应用外导出文件及系统备份／设备迁移副本可能继续保留。备份密码加密只保护导出的备份，不加密应用内笔记。请妥善保管密码；忘记密码无法恢复加密备份。销毁记录不保证闪存取证级安全擦除，也不能撤回应用外副本。
